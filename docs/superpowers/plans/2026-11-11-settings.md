# Settings and Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Settings view where each teammate enters their own keys and preferences (stored on their Mac, never shown again), workday hours with no default and a per-day saved target, and a Light-by-default theme with a toggle across the whole dashboard.

**Architecture:**
- `lib/settings.js` owns `data/settings.json`. It resolves each field as Settings value, then `.env`, then the default, and returns a masked public view.
- On save, the server pushes the resolved values into the existing live config objects (`JIRA`, `TEMPO`, a new `LOCAL`, a new `TIME`), so the many readers need no refactor. It then rebuilds the clients held on `ctx`.
- The browser reads the masked view only.

**Tech Stack:** Node 20, `node:test`, no npm dependencies. Vanilla ES modules in `public/`.

**Spec:** `docs/superpowers/specs/2026-11-11-settings-design.md`

## Global Constraints

- Node 20, zero npm dependencies, `127.0.0.1` only, `textContent` only, `execFile` with no shell
- Non-GET routes need `X-Dashboard: 1`, and the Host check stays
- **Secret fields:** `jira.token`, `tempo.token`, `teams.webhookUrl`, and `teams.testWebhookUrl`. They never appear in any response, log line, or error. The public view shows only `{ set, last4, source }`, and webhooks also show `host`.
- `data/settings.json` is written atomically (tmp file plus rename) with mode `0600`
- **Precedence per field:** Settings value, then `.env`, then the default
- **Tests:** they never read the real `.env` or the real `data/settings.json`. Under `NODE_TEST_CONTEXT`, the default settings are in memory: `{ time: { dayHours: 7 } }` for existing tests. New tests inject their own.
- **Workday hours:** 4–10 in 0.5h steps, with no default. A record saved before this change counts as 7.
- **Theme values:** `light` (default), `dark`, and `system`
- **Copy:** AP Style, title-case headings, contractions, no first person
- Don't run `git commit`

## Review Focus

1. **A saved secret leaking back:** GET, a PUT response, a validation error, or a Test Connection error that echoes a typed token. Expected: never. Pinned in Task 1 by `public view never contains secret values` and in Task 3 by `test errors never echo the candidate token`.
2. **Changing workday hours after confirming days:** past days keep their own target and still re-save. Pinned in Task 4 by `changing dayHours keeps past days' targets`.
3. **A teammate with no settings at all:** the app loads, GitHub views work, Home shows the Connect Jira banner, and Time shows the set-hours prompt. Nothing throws. Pinned in Task 2 by `empty settings and no env still serve every GET route` and in Task 4 by `time is off until dayHours is set`.
4. **A save that should apply without a restart:** a new Jira token is used on the very next Jira call, and a new clone path by the next month build. Pinned in Task 2 by `saving jira rebuilds the client and clears account id`.
5. **A corrupt or hand-edited `settings.json`:** the server starts with defaults and moves the bad file aside, never overwriting it. Pinned in Task 1 by `corrupt file is moved aside`.

### Task 1: Settings Store, Resolution, Validation, and Public View

**Files:**
- Create: `lib/settings.js`
- Test: `test/settings.test.js`

**Interfaces:**
- Produces:
  - `createSettings({ file: string | null, env = process.env, initial = {} }) → Settings`. A `null` file means in memory only.
  - `Settings.raw() → object`: the stored values, which may include secrets. Server only.
  - `Settings.resolved() → Resolved`: Settings, then env, then default, per field
  - `Settings.publicView() → PublicView`: masked
  - `Settings.update(patch) → PublicView`: validates, merges, saves, and returns the masked view. Throws `HttpError(400, msg)` on invalid input. In the patch, a field set to `null` removes the stored value.
  - `validateSettingsPatch(patch, { exists = existsSync }) → string | null`: an error message, or null when the patch is valid
  - `Resolved` shape, with env names in parentheses:
    ```
    { jira: { baseUrl (JIRA_BASE_URL), email (JIRA_EMAIL), token (JIRA_TOKEN) },
      tempo: { token (TEMPO_TOKEN) },
      teams: { webhookUrl (TEAMS_WEBHOOK_URL), testWebhookUrl (TEAMS_TEST_WEBHOOK_URL),
               always: string[] (TEAMS_ALWAYS), never: string[] (TEAMS_NEVER), people: { login: email } (TEAMS_PEOPLE) },
      theme: 'light'|'dark'|'system' (default 'light'),
      time: { dayHours: number|null (no env, default null), reminderOn: boolean (TIME_REMINDER !== 'off', default true),
              reminderAt: 'HH:MM' (TIME_REMINDER when it looks like HH:MM, default '20:30'), mobileClockPath (MOBILE_CLOCK_PATH, default ~/Downloads/GitHub/mobile-clock) },
      builds: { defaultChecked: string[] (default ['mcAndroid','mkAndroid','mcIos','mkIos']) },
      notifications: boolean (default true) }
    ```
    Use the real `BUILDS` keys from `config.js` for the 4 store builds. `mcIosSim` is never allowed in `defaultChecked`.
  - `PublicView` is the same shape with these differences:
    - each secret becomes `{ set, last4, source: 'settings'|'env'|null }`, and webhooks add `host`
    - each non-secret group adds `sources: { field: 'settings'|'env'|'default' }`
    - top-level `configured: { jira: boolean, tempo: boolean, teams: boolean, teamsTest: boolean }`
- **Validation rules (exact messages):**
  - `jira.baseUrl` must match `^https://[a-z0-9-]+\.atlassian\.net/?$`. Message: `Jira URL must look like https://yourcompany.atlassian.net.`
  - `jira.email` must be a valid email. Message: `Enter a valid email address.`
  - Each token must be non-empty, at most 500 characters, with no whitespace. Message: `That token doesn't look right. Paste it again without spaces.`
  - Teams URLs must pass the existing `validWebhookUrl` from `lib/teams.js`. Message: `Use a Teams Workflows webhook address.`
  - `teams.always` and `teams.never` must be arrays of `/^[A-Za-z0-9-]{1,39}$/`
  - `teams.people` must be an object of login to email
  - `theme` must be one of the 3 values
  - `time.dayHours` must be a number from 4 to 10 in 0.5 steps. Message: `Workday hours must be 4–10 in 0.5h steps.`
  - `time.reminderAt` must match `^([01]\d|2[0-3]):[0-5]\d$`
  - `time.mobileClockPath` must be an absolute path that `exists`, with `.git` inside. Message: `That folder isn't a mobile-clock clone.`
  - `builds.defaultChecked` must be a subset of the 4 store keys
  - `notifications` and `time.reminderOn` must be booleans
  - Unknown keys are rejected with `Unknown setting: <key>.`

### Task 3: Test Connection

**Files:**
- Modify: `server.js`, or a small `lib/settings-test.js` if `server.js` grows past readability
- Test: `test/settings-connection.test.js`

**Interfaces:**
- Consumes: Tasks 1 and 2, `createJira`, `createTempo`, `validWebhookUrl`, `getLogin`
- Produces `POST /api/settings/test/:service`, where `service` is one of `github`, `jira`, `tempo`, `teams`, or `teamsTest`. The body has candidate fields for that service, the same shape as a patch section. The route returns `{ ok: boolean, message: string }`. Candidates go through `validateSettingsPatch` first. A validation error gives `{ ok: false, message }` with status 200, and nothing is stored.
  - **github:** `gh auth status`, then `getLogin`. Messages are `Signed in as <login>.` or `Not signed in. Run gh auth login in Terminal.`
  - **jira:** merge the candidates over the resolved Jira values, then `createJira(merged).myself()`. Messages are `Connected as <displayName>.` or `Jira said: <error message>`, where the error message comes from `JiraError`, which never contains the token.
  - **tempo:** if Jira isn't configured, the message is `Connect Jira first. Tempo uses your Jira account to find your worklogs.` Otherwise, use the Jira `myself().accountId` and run `createTempo({ token: candidate ?? resolved }).worklogs(id, today, today)`. Messages are `Connected.` or the Tempo error message.
  - **teams / teamsTest:** run `validWebhookUrl` only. Messages are `Looks right. To see a real message, use test mode in Request Review.` or `Use a Teams Workflows webhook address.` It never fetches.
- Injection for tests: `ctx.makeJira` (default `createJira`), `ctx.makeTempo` (default `createTempo`), and `ctx.gh`
